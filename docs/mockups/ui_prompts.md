# Промты для генерации UI-макетов по архитектурно значимым UC

Каждый промт самодостаточен — можно копировать в новый чат без дополнительного контекста.

Формат по умолчанию для каждого промта: **свёрстанный HTML+CSS макет в одном файле**, без JS, с эстетикой ретро-терминала Fallout (зелёный моноширинный текст на чёрном фоне, рамки из ASCII-символов или тонкие `1px solid #33ff66`, шрифт Share Tech Mono / VT323 / Courier). При необходимости замените формат (Figma-описание, SVG, скриншот) в последней строке промта.

## UC-1 — Создать заявку на перевозку (стационарный терминал, Диспетчер)

```
Ты проектируешь UI для информационной системы «Караваны» — вымышленной платформы управления караванными перевозками в сеттинге Fallout: New Vegas (постапокалиптическая Пустошь, доставка грузов браминами между поселениями).

Свёрстай HTML+CSS-макет экрана «Создание заявки на перевозку» для диспетчера караванной компании. Экран открывается в браузере на стационарном терминале (обычный ПК, разрешение 1280×720).

Стилистика — ретро-терминал RobCo: моноширинный зелёный текст (#33ff66) на чёрном фоне (#0a0f0a), тонкие рамки, ASCII-декор, эффект лёгкого скан-лайна, шрифт Share Tech Mono или VT323.

На экране должны быть:
- Шапка с названием системы «CARAVAN // DISPATCH TERMINAL», именем текущего пользователя и названием организации (например, «Crimson Caravan Company»).
- Левая панель навигации: Реестр рейсов, Новая заявка (активна), Команда, Склад, Отчёты, Админ.
- Форма «Новая заявка на перевозку» с полями: пункт отправления (выбор из списка поселений Пустоши — Goodsprings, Primm, Nipton, New Vegas, Novac), пункт назначения, желаемая дата отправки, описание груза, выбор маршрута (выпадающий список шаблонов + кнопка «Ручной маршрут»), поле «Ценность груза (крышек)».
- Справа — панель «Оценка рейса» с рассчитанными: ETA, risk_score (цветной индикатор: низкий/средний/высокий/критический), рекомендация по составу охраны и объёму припасов.
- Внизу — кнопки «Сохранить черновик» и «Отменить».
- В момент, когда Wasteland Intel недоступен, показать предупреждение «⚠ WASTELAND INTEL OFFLINE — risk_score будет пересчитан позже» вместо цифрового значения.

Сдай один HTML-файл со встроенным CSS. Макет статичный, без JS.
```

## UC-7 — Рассчитать risk_score (стационарный терминал, Диспетчер)

```
Ты проектируешь UI для информационной системы «Караваны» — платформы управления караванными перевозками в сеттинге Fallout: New Vegas.

Свёрстай HTML+CSS-макет виджета «Расчёт risk_score маршрута», отображаемого внутри карточки заявки в веб-интерфейсе диспетчера. Браузер на стационарном терминале (1280×720).

Стилистика — ретро-терминал RobCo: моноширинный зелёный текст (#33ff66) на чёрном фоне (#0a0f0a), тонкие рамки, ASCII-декор, шрифт Share Tech Mono или VT323.

В виджете должно быть:
- Заголовок «RISK ASSESSMENT // MOJAVE WASTELAND».
- Перечень сегментов маршрута (например: Goodsprings → Primm → Nipton → Novac) с индикатором риска на каждом участке (низкий/средний/высокий/критический) и списком угроз (рейдеры NCR, мутанты, радиация, Ceasar's Legion).
- Индикатор «Дата актуальности данных Wasteland Intel» с временной меткой.
- Блок «Коэффициент ценности груза»: слайдер или число, влияющее на итоговый risk_score.
- Итоговый большой индикатор risk_score (0–100) с цветной шкалой и текстовой меткой уровня.
- Рекомендация: «Минимальный состав охраны: N человек. Припасы: вода Xл, патроны Y, стимпаки Z».
- Покажи три состояния виджета (три варианта, друг под другом):
  1. Успешный расчёт с актуальными данными.
  2. Данные устаревшие (старше 24 часов) — жёлтая плашка «⚠ ДАННЫЕ УСТАРЕЛИ».
  3. Wasteland Intel недоступен — красная плашка «✕ WASTELAND INTEL OFFLINE», risk_score = «Н/Д», кнопка «Повторить расчёт».

Сдай один HTML-файл со встроенным CSS. Макет статичный, без JS.
```

## UC-16 — Подтвердить ключевые этапы рейса (смартфон, Караван-мастер)

```
Ты проектируешь UI для информационной системы «Караваны» — платформы управления караванными перевозками в сеттинге Fallout: New Vegas. В мире проекта караван-мастер пользуется устройством Pip-Boy, но в реальной реализации это прогрессивное веб-приложение (PWA), которое караван-мастер открывает в браузере на обычном смартфоне.

Свёрстай HTML+CSS-макет мобильного экрана «Подтверждение ключевых этапов рейса» для караван-мастера. Целевое устройство — смартфон в вертикальной ориентации (viewport 390×844, iPhone-подобный), touch-интерфейс, крупные тап-цели (минимум 44×44), адаптивная вёрстка.

Стилистика — отсылка к эстетике Pip-Boy, но как современный мобильный интерфейс: моноширинный зелёный текст (#33ff66) на чёрном фоне (#0a0f0a), тонкие рамки и акценты, шрифт Share Tech Mono или VT323 для заголовков, системный sans-serif для основного текста (чтобы оставалось читаемо). Не имитируй CRT-физику и сканлайны слишком агрессивно — экран должен быть удобен под пальцы и хорошо читаться на солнце.

На экране:
- Шапка с идентификатором рейса («CARAVAN RUN #C-2287-04») и текущим статусом (EN ROUTE / READY / DELAYED) — sticky, вверху.
- Индикатор статуса связи прямо под шапкой: «● ONLINE» (зелёный) или «◌ OFFLINE — 3 события в очереди» (жёлтый), крупный.
- Прогресс-бар рейса (горизонтальный, показывает, сколько этапов пройдено).
- Список этапов рейса — вертикально, карточками с крупным текстом:
  - [✓] Загрузка завершена — 08:14 / Goodsprings Supply Depot
  - [✓] Выход каравана — 08:42 / Goodsprings
  - [▶] Прибытие на контрольную точку Primm — ТЕКУЩИЙ (выделить рамкой/цветом)
  - [ ] Прохождение КПП NCR
  - [ ] Прибытие на контрольную точку Nipton
  - [ ] Доставка груза — Novac
- Большая sticky-кнопка внизу экрана на всю ширину: «ПОДТВЕРДИТЬ ТЕКУЩИЙ ЭТАП» (высота ~60px, контрастная).
- Под кнопкой — маленький read-only блок с текущими координатами и временем (заполняются автоматически при нажатии).

Сделай два варианта экрана друг под другом (или в iframe-фреймах смартфона):
1. Онлайн-режим, связь есть.
2. Офлайн-режим с пометкой, что 3 события ждут синхронизации.

Сдай один HTML-файл со встроенным CSS. Макет статичный, без JS, но вёрстка должна быть реально адаптивной и удобной на тачскрине (без ховер-only элементов).
```

## UC-19 — Зафиксировать инцидент (смартфон, Караван-мастер / Капитан охраны / Полевой медик)

```
Ты проектируешь UI для информационной системы «Караваны» — платформы управления караванными перевозками в сеттинге Fallout: New Vegas. В мире проекта полевые пользователи пользуются Pip-Boy, но в реальной реализации это прогрессивное веб-приложение (PWA), которое пользователь открывает в браузере на обычном смартфоне.

Свёрстай HTML+CSS-макет мобильного экрана «Фиксация инцидента» для полевого пользователя (караван-мастер, капитан охраны или полевой медик). Целевое устройство — смартфон в вертикальной ориентации (viewport 390×844), touch-интерфейс, крупные тап-цели (минимум 44×44), адаптивная вёрстка. Ситуация стрессовая — пользователь вносит данные в полевых условиях, возможно под огнём. Форма должна быть максимально быстрой к заполнению.

Стилистика — отсылка к эстетике Pip-Boy, но как современный мобильный интерфейс: моноширинный зелёный текст (#33ff66) на чёрном фоне (#0a0f0a), тонкие рамки и акценты, шрифт Share Tech Mono / VT323 для заголовков, системный sans-serif для ввода и подписей (чтобы оставалось читаемо). Не перегружай CRT-эффектами — интерфейс должен быть удобен под пальцы.

На экране:
- Шапка «ОТЧЁТ ОБ ИНЦИДЕНТЕ // РЕЙС #C-2287-04», sticky вверху.
- Автоматически заполненная панель (read-only, серым/приглушённым): время, координаты (типа «N36°47.012' W115°26.884'»), кнопка-иконка «обновить GPS».
- Тип инцидента — крупные плитки-кнопки (2 в ряд), которые выбираются тапом: НАПАДЕНИЕ, КОГОТЬ СМЕРТИ, ПОЛОМКА, МЕД. ЭКСТРЕННАЯ СИТУАЦИЯ, ПОТЕРЯ ГРУЗА, ШТОРМ/РАДИАЦИЯ, ПРОЧЕЕ. Выбранная плитка подсвечивается.
- Тяжесть — крупный segmented control (4 сегмента): НИЗКАЯ / СРЕДНЯЯ / ВЫСОКАЯ / КРИТИЧЕСКАЯ — с визуальным градиентом от зелёного к красному, минимум 48px высотой.
- Текстовое поле «Описание» (textarea, 4–5 строк), с placeholder-подсказкой.
- Список участников команды с тумблерами/чекбоксами для отметки пострадавших (ФИО + роль: Караван-мастер Дж. Кассиди, Капитан охраны А. Сэнт-Джеймс, Полевой медик М. Гаррет, Погонщик браминов Б. Райт).
- Большая sticky-кнопка внизу на всю ширину: «ОТПРАВИТЬ ОТЧЁТ» (минимум 60px высотой, красный/янтарный акцент при выборе критической тяжести).
- Индикатор связи в шапке: ● ONLINE или ◌ OFFLINE.

Сделай три варианта экрана друг под другом (или в трёх фреймах смартфона):
1. Форма в процессе заполнения (что-то выбрано, что-то нет).
2. Экран успешного сохранения: зелёный чек, сообщение «ИНЦИДЕНТ ЗАРЕГИСТРИРОВАН — ДИСПЕТЧЕР УВЕДОМЛЁН».
3. Офлайн-режим после подтверждения: «◌ ОФЛАЙН — ОТЧЁТ В ОЧЕРЕДИ, СИНХРОНИЗАЦИЯ ПРИ ВОССТАНОВЛЕНИИ СВЯЗИ».

Сдай один HTML-файл со встроенным CSS. Макет статичный, без JS, но вёрстка должна быть реально адаптивной и удобной на тачскрине (без ховер-only элементов).
```

## UC-32 — Создать организацию (стационарный терминал, Суперпользователь)

```
Ты проектируешь UI для информационной системы «Караваны» — платформы управления караванными перевозками в сеттинге Fallout: New Vegas. Платформа мультитенантная: суперпользователь (администратор платформы, не сотрудник конкретной компании) создаёт организации (караванные компании) и назначает им первых диспетчеров.

Свёрстай HTML+CSS-макет экрана «Административная панель: создание организации» для суперпользователя. Браузер на стационарном терминале (1280×720).

Стилистика — ретро-терминал RobCo, но с акцентом на «административный режим»: моноширинный янтарный текст (#ffb000) на тёмно-сером фоне (#141414), тонкие рамки, ASCII-декор, шрифт Share Tech Mono или VT323. Отличие от обычного диспетчерского интерфейса — янтарная палитра вместо зелёной (чтобы визуально подчеркнуть роль суперпользователя).

На экране:
- Шапка «ROBCO PLATFORM // SUPERUSER CONSOLE» с именем суперпользователя.
- Левая панель навигации: Organizations (активно), Subscriptions, Audit Log, System Health.
- Центральная область — двухшаговый мастер создания организации:
  - Шаг 1: Данные организации — название (с пометкой «Должно быть уникальным»), уровень подписки (BASIC / STANDARD / PRO — карточки), юридический адрес, основной контакт.
  - Шаг 2: Первый диспетчер — ФИО, логин, начальный пароль, email/голофон. Чекбокс «Пропустить (назначить позже)».
- Справа — сводка «SUMMARY»: что будет создано (организация + пользователь + изолированное пространство данных).
- Внизу — кнопки «BACK», «NEXT», «CREATE ORGANIZATION».
- Над формой — информационная плашка: «Создание организации изолирует её данные от других организаций платформы. Суперпользователь сохраняет полный доступ ко всем организациям.».
- Покажи также состояние ошибки: при попытке ввести неуникальное название — красная плашка «✕ Organization name «Crimson Caravan Company» already exists».

Сдай один HTML-файл со встроенным CSS. Макет статичный, без JS.
```

## Советы по использованию

- Для каждого промта начинай **новый чат**, чтобы контексты не смешивались.
- Если хочешь Figma-спецификацию вместо HTML — замени последний абзац на: «Опиши макет в формате Figma-спецификации: компоненты, auto-layout, типографика, цвета, состояния».
- Для генерации скриншота через модели с инструментами картинки (DALL-E, Midjourney, Nano Banana) — замени последний абзац на: «Сгенерируй реалистичный скриншот этого экрана».
- После получения HTML открой в браузере, сделай скриншот — вставь в Vision.md / SDP.md в раздел с UI.
