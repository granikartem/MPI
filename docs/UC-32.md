- [x] Обновить docker-compose/README под фактическую инфраструктуру и новые эндпоинты.

## Результат проверки

- Frontend: `npm run build` выполнен успешно.
- Backend: `docker compose up -d --build backend` выполнен успешно, `gradle test` в Docker выполнен успешно (`test NO-SOURCE`, компиляция Java прошла).
- End-to-end: `GET /api/health`, `GET /api/organizations`, `POST /api/organizations`, конфликт уникального имени и создание без первого диспетчера проверены на поднятом Docker Compose.
- MongoDB: audit-события `ORGANIZATION_CREATED` проверены в коллекции `audit_event`.
- Frontend через compose proxy: `/organizations`, `/requests`, `/api/health`, `/api/organizations` на `http://localhost:5173` отвечают.

## Критерии готовности

- [x] UC-32 создаёт активную организацию с уникальным названием.
- [x] При заполнении данных первого диспетчера создаётся пользователь с ролью `DISPATCHER`, привязанный к организации.
- [x] Можно пропустить первого диспетчера и создать организацию без пользователей.
- [x] Ошибки уникальности возвращаются с backend и отображаются во frontend.
- [x] В MongoDB пишется audit-событие с деталями создания.
- [x] Docker Compose поднимает PostgreSQL, MongoDB, backend и frontend с актуальными переменными окружения.
